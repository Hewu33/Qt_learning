## 一、sender() — 信号发送者追溯

### 是什么

`sender()` 是 `QObject` 的成员函数，在槽函数内部调用，返回**触发当前槽的那个信号发送者的指针**。

### 典型场景

多个发送者连接到同一个槽，槽内部需要知道"是谁触发了我"：

```cpp
// 构造：三个按钮连到同一个槽
connect(btnRed,   &QPushButton::clicked, this, &MyWidget::onColorClicked);
connect(btnGreen, &QPushButton::clicked, this, &MyWidget::onColorClicked);
connect(btnBlue,  &QPushButton::clicked, this, &MyWidget::onColorClicked);

// 槽函数中区分
void MyWidget::onColorClicked()
{
    QPushButton *btn = qobject_cast<QPushButton *>(sender());
    if (!btn) return;

    if (btn == btnRed)       setColor(Qt::red);
    else if (btn == btnGreen) setColor(Qt::green);
    else if (btn == btnBlue)  setColor(Qt::blue);
}
```

### 用法要点

- 必须用 `qobject_cast<>()` 转换类型，直接 C 风格强转不安全
- 只在被信号触发的槽中有效，手动调用槽函数时 `sender()` 返回 `nullptr`
- 跨线程时慎用——槽被放入事件队列后，`sender()` 可能已失效

### 局限性

| 问题 | 说明 |
|------|------|
| 耦合性 | 槽必须知道发送者的类型，破坏了解耦初衷 |
| 不可靠 | 嵌套事件循环或跨线程时可能拿到错误值 |
| 不直观 | 建议优先用 Lambda 显式传参，比 sender() 更清晰 |

**推荐替代（Lambda 闭包）：**

```cpp
connect(btnRed, &QPushButton::clicked, this, [this]() { setColor(Qt::red); });
connect(btnGreen, &QPushButton::clicked, this, [this]() { setColor(Qt::green); });
```

## 二、QObject::disconnect() — 断开信号槽

### 五种常见用法

```cpp
// 1. 断开一个具体连接（最常用）
disconnect(sender, &Sender::signal, receiver, &Receiver::slot);

// 2. 断开 sender 的某个信号的所有连接
disconnect(sender, &Sender::signal, nullptr, nullptr);

// 3. 断开 sender 的所有信号
disconnect(sender, nullptr, nullptr, nullptr);

// 4. 断开 receiver 收到的所有信号
disconnect(nullptr, nullptr, receiver, nullptr);

// 5. 断开一个 QMetaObject::Connection 对象
QMetaObject::Connection conn = connect(...);
disconnect(conn);
```

### 典型场景

**场景 1：一次性连接（执行一次后自动断开）**

```cpp
QMetaObject::Connection conn;
conn = connect(btn, &QPushButton::clicked, [&conn]() {
    qDebug() << "只执行一次";
    disconnect(conn);  // 执行后自毁
});
```

**场景 2：切换模式时重新绑定**

```cpp
// 编辑模式 → 只读模式时，断开编辑相关的信号
disconnect(table, &QTableWidget::cellChanged, this, &MyWidget::onCellEdit);
```

## 三、连接类型：Auto / Direct / Queued

`connect()` 的第五个参数（默认 `Qt::AutoConnection`）：

```cpp
connect(sender, &Sender::signal, receiver, &Receiver::slot, Qt::XxxConnection);
```

### 三种类型对比

| 类型 | 槽执行时机 | 执行线程 | 适用场景 |
|------|-----------|---------|---------|
| `Qt::AutoConnection` | 自动判断 | 自动 | **默认，99% 的场景** |
| `Qt::DirectConnection` | 信号发射的瞬间 | 发送者线程 | 同线程内需要立即响应 |
| `Qt::QueuedConnection` | 接收者事件循环下次轮询 | 接收者线程 | **跨线程通信（核心）** |

### 直观类比

```
DirectConnection  = 打电话（即时响应，对面说完你马上回答）
QueuedConnection  = 发微信（消息放入队列，对方有空再处理）
AutoConnection    = 自动选——面对面就直接说，异地就发微信
```

### DirectConnection 示意图

```
发送者线程                         接收者线程
    │                                  │
    ├─ emit signal()                   │
    │   └─ 直接调用 slot() ← 同线程     │
    │   └─ slot() 执行完毕              │
    ├─ emit 之后的代码继续执行           │
```

### QueuedConnection 示意图

```
发送者线程                         接收者线程
    │                                  │
    ├─ emit signal()                   │
    │   └─ 把 slot 调用放入队列         │
    ├─ emit 之后的代码立即继续          │
    │                                  ├─ 事件循环轮询到队列中的 slot
    │                                  ├─ 执行 slot()
    │                                  └─ slot() 执行完毕
```

### 关键区别：QueuedConnection 的槽参数会被复制

```cpp
// 信号
signal: void dataReady(QString data);

// QueuedConnection 时：data 会被复制一份放入事件队列
// DirectConnection 时：data 直接传递（引用也可以）
```

这意味着跨线程时，**信号的参数类型必须注册到 Qt 元对象系统**（Qt 内置类型如 QString、int 已自动注册，自定义类型需要 `qRegisterMetaType<>()`）。

### 当前阶段只需记住

- `AutoConnection` 是默认值，同线程就是同步调用，跨线程就是异步调用
- 线程阶段（第 13 周）之前，你写的所有代码都是同线程，所以三种类型行为完全一样
- 真正需要关心的是 **第 13 周学多线程时**，`QueuedConnection` 会成为跨线程更新 UI 的关键

## 四、创建两个独立窗口

### 步骤概览

```
1. 创建第二个窗口类（WindowB.h / WindowB.cpp）
2. 在 WindowB 中声明自定义信号（用于向外部发送数据）
3. 在 WindowB 中声明自定义槽（用于接收外部数据）
4. 在 main.cpp 中创建两个窗口对象，用 connect() 桥接
```

### 完整代码

**WindowB.h — 第二个窗口的头文件**

```cpp
#ifndef WINDOWB_H
#define WINDOWB_H

#include <QWidget>
#include <QLineEdit>

class WindowB : public QWidget
{
    Q_OBJECT

public:
    explicit WindowB(QWidget *parent = nullptr);

public slots:
    void onMessageReceived(const QString &msg);  // 接收外部消息

signals:
    void messageSent(const QString &msg);        // 向外发送消息

private:
    QLineEdit *lineEdit;
};

#endif
```

**WindowB.cpp — 第二个窗口的实现**

```cpp
#include "WindowB.h"
#include <QVBoxLayout>
#include <QPushButton>
#include <QLabel>

WindowB::WindowB(QWidget *parent)
    : QWidget(parent)
{
    setWindowTitle("窗口 B");

    auto *label = new QLabel("收到的消息将显示在这里", this);
    lineEdit = new QLineEdit(this);
    auto *sendBtn = new QPushButton("发送给窗口 A", this);

    auto *layout = new QVBoxLayout(this);
    layout->addWidget(label);
    layout->addWidget(lineEdit);
    layout->addWidget(sendBtn);

    // 点击发送按钮 → 发出 messageSent 信号
    connect(sendBtn, &QPushButton::clicked, this, [this]() {
        emit messageSent(lineEdit->text());
    });
}

void WindowB::onMessageReceived(const QString &msg)
{
    lineEdit->setText("A 说: " + msg);  // 收到消息后显示在输入框中
}
```

**MainWindow.h — 主窗口，加一个输入框和发送按钮**

```cpp
#ifndef MAINWINDOW_H
#define MAINWINDOW_H

#include <QMainWindow>
#include <QLineEdit>

class MainWindow : public QMainWindow
{
    Q_OBJECT

public:
    explicit MainWindow(QWidget *parent = nullptr);

signals:
    void messageSent(const QString &msg);

public slots:
    void onMessageReceived(const QString &msg);

private:
    QLineEdit *lineEdit;
};

#endif
```

**MainWindow.cpp**

```cpp
#include "MainWindow.h"
#include <QVBoxLayout>
#include <QPushButton>
#include <QLabel>
#include <QStatusBar>

MainWindow::MainWindow(QWidget *parent)
    : QMainWindow(parent)
{
    auto *central = new QWidget(this);
    setCentralWidget(central);

    auto *label = new QLabel("窗口 A - 主窗口", central);
    lineEdit = new QLineEdit(central);
    auto *sendBtn = new QPushButton("发送给窗口 B", central);

    auto *layout = new QVBoxLayout(central);
    layout->addWidget(label);
    layout->addWidget(lineEdit);
    layout->addWidget(sendBtn);
    layout->addStretch();

    statusBar()->showMessage("就绪");

    // 点击按钮 → 发出信号
    connect(sendBtn, &QPushButton::clicked, this, [this]() {
        emit messageSent(lineEdit->text());
    });
}

void MainWindow::onMessageReceived(const QString &msg)
{
    lineEdit->setText("B 说: " + msg);
    statusBar()->showMessage("收到来自窗口 B 的消息", 3000);
}
```

**main.cpp — 创建两个窗口并连接信号**

```cpp
#include <QApplication>
#include "MainWindow.h"
#include "WindowB.h"

int main(int argc, char *argv[])
{
    QApplication a(argc, argv);

    MainWindow wA;  // 窗口 A
    WindowB    wB;  // 窗口 B

    // 核心：跨窗口信号槽连接
    // A 发信号 → B 的槽接收
    QObject::connect(&wA, &MainWindow::messageSent, &wB, &WindowB::onMessageReceived);
    // B 发信号 → A 的槽接收
    QObject::connect(&wB, &WindowB::messageSent, &wA, &MainWindow::onMessageReceived);

    wA.show();
    wB.show();

    return QApplication::exec();
}
```

### 关键图解

```
┌──────────────┐                    ┌──────────────┐
│   MainWindow │                    │   WindowB    │
│   (窗口 A)   │                    │   (窗口 B)   │
│              │  emit messageSent──→ onMessageReceived
│  输入框      │                    │  输入框      │
│  发送按钮    │                    │  发送按钮    │
│              │←─onMessageReceived │              │
│              │    emit messageSent│              │
└──────────────┘                    └──────────────┘
         ↕ connect()                        ↕
    ┌─────────────────────────────────────────┐
    │              main.cpp                   │
    │  connect(&wA, signal, &wB, slot);      │
    │  connect(&wB, signal, &wA, slot);      │
    └─────────────────────────────────────────┘
```

## 五、跨窗口通信的核心模式

### 模式 1：直接 connect（上面示例，最常用）

适用：两个窗口在同一个 main 函数中都能访问到时。

### 模式 2：子窗口通过信号回传（推荐）

适用：主窗口弹出子窗口，子窗口关闭时需要传回数据。

```cpp
// 主窗口弹出子窗口时建立连接
void MainWindow::openChildWindow()
{
    auto *child = new MyDialog(this);  // 子窗口

    // 在子窗口"确认"信号发出时接收数据
    connect(child, &MyDialog::confirmed, this, [this](const QString &data) {
        // 拿到子窗口回传的数据，更新主窗口 UI
        ui->label->setText(data);
    });

    child->show();  // 非模态
}
```

### 模式 3：信号链（A → B → C）

```cpp
connect(&objA, &A::sig, &objB, &B::slot);  // A 触发 B 的槽
// B 的 slot 内部 emit 另一个信号
// objC 接收 B 的信号
connect(&objB, &B::forwarded, &objC, &C::handler);
```
